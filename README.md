# 拼豆计数器

一个只给自己用的网页应用（PWA）：添加一张拼豆图纸截图 → 读出每种色号和数量 → **人工核对** → 存进图纸库 → **开始拼豆**（数字化的拼豆板，一个颜色一个颜色地拼、打勾）→ 拼完扣库存、提醒补货。装在 iPhone 主屏幕上，像 App 一样全屏打开；所有数据只存在手机本地。拼的时候也可以把拼豆板扫到 **iPad** 上看（「拼豆看板」，见“在 iPad 上拼”）。

底部三个标签：**图纸**（图纸库、添加图纸、开始拼豆）· **库存**（库存和流水）· **设置**。

## 功能

| 模块 | 说明 |
| --- | --- |
| 图纸库 | 所有图纸一目了然：名字、状态（待拼 / 拼豆中 / 已拼）、分类、用到的颜色（一排色块，**左右滑动看全部**）；按名字**搜索**，按状态、**分类**筛选（选几个分类 = 同时带有这些分类的图纸） |
| 图纸详情 | **改名**、**加分类**（一张图纸可以有多个分类；分类可以改名、删除）、看原图、库存对照（还要用多少、现在有多少、拼完剩多少）、开始拼豆、修改颜色和数量、复制一份再拼、删除 |
| 开始拼豆 | 先**准备拼豆板**（每一步一页，“下一步”一直在屏幕底部）：① 在原图上**框出拼豆板** → ② **网格**：看红线和格子对没对齐，显示图纸几列几行、有豆子的范围、豆子总数 → ③ **颜色**：颜色很接近的几种**自动逐格读色号**，读完还有没把握的格子**直接弹出核对**（都不用点，都在选尺寸之前）；每种颜色的格数和清单对一对 → ④ **选自己的拼豆板尺寸**（点选存好的常用尺寸，如 52×52、78×78、104×104，或输入宽×高；放不下整幅图的尺寸不能选；可存为常用、可删）→ ⑤ 整幅图**上下左右平移**摆好（不会超出拼豆板）。然后是**数字化的拼豆板**：可双指缩放，每 5 格一条粗引导线（位置和实物拼豆板一样：52×52 两边各空 1 颗、78×78 各空 4 颗、104×104 各空 2 颗再画）、边上标行列号（**放大后行号固定在左边、列号固定在上边**）；颜色默认**颗数多的先拼**（也可以选少的先拼、按色号、按清单顺序）；**选一个颜色时，正在拼的是深色、已经拼好的是浅色、还没拼的先不画**（像手上的拼豆板；也可以换成“三种深浅”）；可一键**高亮当前颜色**（其他颜色变暗）、一键**镜像**（左右翻转，从背面熨烫/照着反面拼时用）；拼好一个颜色点“拼好了”打勾；全部打勾后“全图已拼好”→ 确认后扣库存 |
| 在 iPad 上拼 | **拼豆看板**（iPad 主屏幕上另一个图标）：iPhone 上开始拼豆 → **📲 iPad** 出二维码，iPad 扫一下，拼豆板就在大屏幕上（选颜色、高亮、镜像、打勾都一样，横屏颜色在右边一栏）；拼完在 iPhone 上点“🎉 全拼好了”扣库存；中途结算时 iPad 出一个进度码，iPhone 扫回来。两台设备之间只用二维码传，库存和图纸只在 iPhone 上 |
| 试用激活 | 给朋友试用：每台设备要有你给的激活码才能用（和设备绑定，转给别人没用；7 / 30 / 90 天或永久，到期后数据还在）；你的手机导入作者密钥后，在 设置 → 试用激活码 里生成。不需要服务器 |
| 撤回为待拼 | 点了开始拼豆又不想拼了：“拼豆中”的图纸可以**撤回为待拼**（打的勾清空，这次扣过的库存加回来，拼豆板和摆放位置保留）；第一次设置拼豆板时直接退出，图纸也还是“待拼” |
| 中途结束 | “先拼到这里”：打了勾的颜色扣库存（拼上去的豆子挑不下来），没拼好的颜色放回库存（不扣）；某个颜色拼了一部分可以填用掉几颗；可选“以后接着拼”（进度保留，以后只扣剩下的）或“这次不拼了”（图纸放回**待拼**，详情页记着上次拼到哪、扣了什么） |
| 拼豆板校正 | **核对拼豆板**（准备拼豆板的“颜色”那一步，或拼豆页 ⋯ 里）：只问几格（颜色很接近的每种问一格、没把握的格子逐个问），确认后整板按这些格子重新计算，认反了的颜色一起纠正；也可以让识字模型自动读几格核对；点格子手动改（改过的格子会锁定，重新生成也保留）；和清单颗数对一对；没有格线、自动识别失败的图可以**手动校准**（填几列几行，在原图上点左上角、右下角）；**去水印**（默认开，可关）：被水印、半透明文字盖住的格子也认得准，还能看去掉水印后的图 |
| 识字模型 | **设置 → 识字模型**：读拼豆板格子上印的色号（逐格读色号、识字核对）用 **高精度**（PP-OCRv6 small，默认，更准）或 **标准**（PP-OCRv5 mobile，更小更快）；可以先“现在下载”，之后离线可用。读清单一直用标准模型 |
| 识别方法（设置里开关，可同时开多个） | **云端大模型**：Claude / OpenAI / Gemini 三选一，手机直连或经 Cloudflare Worker 代理；**离线 OCR**：手机上跑 PP-OCR（PP-OCRv5，默认）或 Tesseract（轻量），免费不联网；**实况文本 / 快捷指令**：用 iPhone 自带的 Apple Vision 文字识别，粘贴文字解析 |
| 开启校验 | 打开某个方法时必须填好它需要的全部参数（服务商、API Key 或 Worker 地址+口令、模型名），并通过一次自检（发一张测试图，确认能读对）才会真正启用 |
| 多图合并 | 一张图纸拆成几张截图（上下滚动截的、或者切成上下左右几块）：选图时一次选几张，**自动拼成一张大图**——找出每两张之间重叠的地方、逐像素对齐，重叠部分只留一份（顺序乱了也没关系，大小不一样的按格子间距缩放到一样）；找不到重叠的（刚好切在边上、或者有一张只是清单）**手动排**：调顺序、选上下拼 / 左右拼 / 每行几张，直接接在一起。拼好的大图用来识别清单、生成拼豆板 |
| 框选清单 | 自动猜清单位置（最后一条长格线以下），可拖动调整；很长的拼图默认只显示清单附近那一段（可以“显示整张”） |
| 识别总览 | 识别完先看一眼（**先核对颜色齐不齐，再逐项核对数量**；补上漏掉的颜色后仍留在总览，可以接着对着整张图找）：清单图上把识别出的每一项框出来（绿=读出来了，黄=把握不大，红=缺色号/数量），**没被框住的就是漏掉的**，点它就能补上；可填图上写的总颗数，自动算差多少颗；同时把图纸网格数字化，和清单**交叉核对**（图上某种颜色的格数和清单差很多、图上有清单里没有的颜色，都会提示） |
| 逐项核对 | 每一项都显示：图中放大的局部（色号实线框、数量虚线框）、识别结果、图中取色 vs 标准色、问题提示（读不出、不在色卡里、重复、颜色对不上、截图太糊）；必须逐项点“对了”才能进入下一步 |
| 保存图纸 | 起名、加分类、对照库存（不够的标红，拼完低于补货线的标黄）→“保存并开始拼豆”或“先存到图纸库” |
| 放大看原图 | 识别时整张图纸会存下来（长边 ≤3000 像素，iPhone 截图保持原尺寸，拼豆板要读格子里的小字）。核对、保存、图纸库、拼豆时都能全屏打开：双指缩放、拖动、双击放大 |
| 扣库存 | **照着拼豆板拼的，按拼豆板上的豆子扣**（和清单数量不一样时以拼豆板为准）；没用拼豆板（选了“不用拼豆板”，或者图纸详情里“不用拼豆板，已经拼完了”）按清单数量扣。一次性扣减（事务，要么全成功要么不变）；库存记录比实际少时扣到 0 为止；可以在图纸详情里撤销（库存加回来，已打的勾保留） |
| 补货提醒 | 扣减后列出低于补货线的颜色；库存页“待补货”筛选；底栏角标 |
| 多选 | 图纸 → 多选：勾几张图纸 → **看合计用量**（可设每张拼几份）：每色 需要 / 现有 / 拼完剩 / 建议买，一键复制采购清单（只是计算，不改库存）；或者 **一起删除** |
| 库存 | 全色卡网格、搜索、按系列筛选（点完筛选按钮那一排不会自己滑走）、**排序**（列表右上角“⇅ 按色号 ▾”：按色号 / 数量少→多（快用完的排最前）/ 数量多→少）、补货 +N、盘点设为、单色补货线；**批量录入**：点选多个颜色一起补货/盘点（颗数自己填）、全部 280 色 / **基础 221 色（A–M）** / 某个系列一次设好、粘贴“色号 数量”列表；“流水”里是每一次库存变动 |
| 色卡管理 | 设置 → 色卡管理：新增、修改（色号 / 颜色 / 名称）、删除颜色；取色可用系统调色盘、输入 HEX 或“从照片取色”；批量导入导出；一键恢复默认 |
| 备份 | 导出 JSON（可存到 iCloud 云盘，可选带上图纸原图）/ 导入恢复 |
| 离线 | Service Worker 缓存，没网也能打开（云端识别除外） |

内置色卡：MARD 280 色 —— A1–A26、B1–B32、C1–C29、D1–D26、E1–E24、F1–F25、G1–G21、H1–H23、M1–M15，P1–P23（珠光）、R1–R28（果冻）、Y1–Y5（夜光）、Q2 / Q5（温变）、T1（透明闪片）。标准色值来自拼豆图鉴 pd.anqstar.com 和 Pixelbead MARD 色卡，A–H、M 已用示例图纸的色块取色核对。可在“设置 → 色卡管理”里自定义。

## 部署到 iPhone（约 10 分钟，全程网页操作）

应用是纯静态网页，需要放到一个 **HTTPS** 网址上，iPhone 才能“添加到主屏幕”并离线使用。推荐 GitHub Pages（免费）。

### 方法一：GitHub Pages（推荐）

1. 用电脑打开 <https://github.com>，注册或登录。
2. 右上角 **+ → New repository**：
   - Repository name 填 `pindou`（随意）
   - 选 **Public**（免费账号的 Pages 需要公开仓库；仓库里只有代码，没有你的库存数据和 API Key）
   - 点 **Create repository**
3. 在新仓库页面点 **uploading an existing file**，把本文件夹（`pindou-app`）**里面的所有文件和子文件夹**一起拖进去（`index.html` 必须在仓库根目录，不要多套一层文件夹），点 **Commit changes**。
4. 仓库 **Settings → Pages**：Source 选 **Deploy from a branch**，Branch 选 **main**、文件夹 **/ (root)**，点 **Save**。
5. 等 1–2 分钟，页面顶部会出现网址：`https://你的用户名.github.io/pindou/`。

### 方法二：Cloudflare Pages

Cloudflare 控制台 → **Workers & Pages → Create → Pages → Upload assets** → 起个项目名 → 把 `pindou-app` 文件夹拖进去 → Deploy。得到 `https://项目名.pages.dev`。

### 装到 iPhone 上

1. 在 iPhone 上用 **Safari** 打开上面的网址。
2. 点底部 **分享** 按钮 → **添加到主屏幕** → 添加。
3. 以后**都从主屏幕图标打开**。注意：iOS 上主屏幕图标和 Safari 标签页是两份独立的数据，只用图标那一份。

### 第一次使用

1. **设置 → 识别方法**：打开至少一种（见下一节）。
2. **库存 → 批量录入**：先选“补货（加上）”或“盘点（设为）”，然后任选一种：点选颜色（可以跨系列多选）填颗数；“按系列 / 整套一次录入”（买了整套基础色卡就选“基础 221 色（A–M）”，全套选“全部 280 色”）；或粘贴“色号 数量”列表。
3. **图纸 → ＋ 添加**：选一张图纸截图，核对后保存；在图纸详情里点“开始拼豆”。
4. **设置 → 库存**：调默认补货线（默认 100 颗）、损耗（默认 0%）、快捷补货按钮。

### 以后更新版本

修改代码后，把 `sw.js` 里的 `VERSION`（格式 `pindou-vX.Y.Z`）和 `js/version.js` 里的 `APP_VERSION`（`X.Y.Z`）一起改成一个**比现在大**的新号（两边数字要一样；现在是多少看 **设置 → 关于**），再重新上传覆盖到**同一个仓库**。手机打开（或从后台切回）App 时会检查新版本，下载好后自动刷新一次就是新版本；正在做事（识别、准备拼豆板、拼豆、弹窗开着）时不打断，顶上出现“新版本已经下载好 · 立即更新”。**设置 → 关于** 里写着现在运行的版本号，也可以点“检查更新”。更新只换代码，库存、图纸等数据不受影响（数据库升级只加不删）；但网址不要变，主屏幕图标不要删，并定期导出备份。

> v2.6.0 以前的版本不会自动刷新，而且可能一直用旧文件（GitHub Pages 让浏览器缓存文件 10 分钟，旧版本装新版本时拿到的还是缓存里的旧文件）。从旧版本升上来时：在 iPhone 上把 App 从后台划掉再打开，必要时再划掉打开一次，看到 **设置 → 关于** 里是新版本号就好了；之后的更新都会自动完成。

### 给朋友试用（转给别人没用）

免费、不用服务器：每台设备有自己的**设备码**，要有你给的**激活码**才能用，激活码只对那一台设备有效。朋友把网址或激活码转给别人都没用——别人打开只会看到自己的设备码，还得来找你要。

**你（作者）先做一次**：你手机上的 App 更新到 v2.8.0 后也会先出现激活页面。点最下面 **我是作者（导入密钥）**，把“拼豆激活密钥.txt”里 `PDKEY1.` 开头的那一整行粘贴进去，这台手机就永久激活了，设置里“关于”下面多了 **试用激活码**。密钥只存在你手机上：**不要放进 GitHub 仓库、不要发给别人**，自己存一份（比如 iCloud 云盘、备忘录）；换手机时再导入一次（设置 → 关于 → 作者：导入密钥）。丢了的话，已经发出去的激活码照样能用，但不能再生成新的。

**给朋友**：
1. 把网址发给朋友：iPhone 用 Safari 打开 → 分享 → **添加到主屏幕** → 从主屏幕打开（Safari 里和主屏幕上是两份数据，要在主屏幕上的 App 里激活；在 Safari 里打开时激活页面会先提醒这一点）。
2. 朋友把激活页面上的**设备码**（像 `K7Q4-M2XD`）发给你。
3. 你在 **设置 → 试用激活码**：填设备码，选能用多久（7 天 / 30 天 / 90 天 / 永久），可以写个备注，点“生成激活码”，把 `PD1` 开头的那串复制发回去。
4. 朋友粘贴、点“激活”。到期后 App 回到激活页面（库存、图纸都还在），你再给一个新的就能接着用。朋友在 设置 → 关于 里能看到还能用几天。

- 激活码是你的私钥对“设备码 + 到期日”的签名（ECDSA P-256），App 里只有公钥：能验证，造不出来；全在手机上算，没网也能验证。
- 挡得住转发，挡不住会改代码的人：网页代码谁都能下载，懂编程的人可以自己拷一份、把激活去掉。给朋友试用够了；要更严得有服务器把关（比如 Cloudflare Pages + Cloudflare Access 邮箱白名单）。
- 朋友清空了网站数据、换了手机，设备码会变，要重新给激活码。
- iPad 看板不用激活（它只能看 iPhone 发过来的拼豆板，自己什么也做不了）。电脑上本地测试（127.0.0.1）也不用激活。

## 三种识别方法怎么配

### 1. 云端大模型（最准，需要 API Key，按次计费）

在 **设置 → 云端大模型** 打开开关，填写：

| 参数 | 说明 |
| --- | --- |
| 服务商 | Claude（Anthropic）/ OpenAI / Gemini |
| 连接方式 | **手机直连**：API Key 只存在手机里；**Worker 代理**：Key 存在你自己的 Cloudflare Worker，手机只存口令 |
| API Key（直连） | Claude：platform.claude.com → API Keys；OpenAI：platform.openai.com → API keys；Gemini：aistudio.google.com → Get API key |
| Worker 地址 + 口令（代理） | 见下文 |
| 模型名称 | 默认 `claude-sonnet-5` / `gpt-5.5` / `gemini-3.8-flash`，可改成你账号能用的其他视觉模型 |
| 两遍识别 | 先让模型定位清单，再裁出来放大读取；更准，每张图多一次调用 |

点 **保存并启用** 会先发一张测试图，读对了才启用。识别时也可以勾选“自己框选清单区域”，省掉定位那一次调用。

**部署 Worker 代理（可选，更安全）**

1. Cloudflare 控制台 → **Workers & Pages → Create → Worker**，名字如 `pindou-proxy` → Deploy。
2. **Edit code**，把 `worker/worker.js` 的内容整个粘贴进去 → **Deploy**。
3. Worker 的 **Settings → Variables and Secrets** 添加（类型选 Secret）：
   - `PROXY_TOKEN`：自己设一个长口令
   - `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY`：用哪家填哪家
   - 可选普通变量 `ALLOWED_ORIGIN`：你的应用网址，如 `https://你的用户名.github.io`
4. 把 Worker 网址（`https://pindou-proxy.xxx.workers.dev`）和口令填进应用设置。

### 2. 离线 OCR（免费、不联网）

**设置 → 离线 OCR** 打开 → 点选引擎（PP-OCR / Tesseract，不用填任何路径）→ **自检并启用**。识别前需要确认清单框选位置。

| 引擎 | 说明 |
| --- | --- |
| **PP-OCR（推荐，默认）** | PaddleOCR 第 5 代识别模型 PP-OCRv5（mobile，也就是“识字模型”里的标准模型），用 ONNX Runtime Web 在手机上跑（单线程 WASM）。只保留色号用得到的 99 个字符，模型 7.6 MB + 运行库 11 MB，第一次约下载 19 MB（随应用部署在 `vendor/ppocr/`、`vendor/ort/`），之后单独缓存、更新应用版本也不用重下。读每个词时只在“色号/数字”这个封闭字表里选，并用 CTC 前向算法在候选色号里挑概率最大的。 |
| Tesseract（轻量） | Tesseract 4（约 7 MB，`vendor/tesseract/`）。PP-OCR 加载失败时也会自动退回它。 |

两者都适合清晰的截图；清单字很小、很糊（字高不到约 10 像素）时都会读错一些，应用会提示“截图分辨率低”，PP-OCR 明显好一些（见下面的测试）。

**识字模型（v2.6）**：读拼豆板格子上印的色号（“逐格读色号”“识字核对”）另外可选模型，**设置 → 识字模型**：

| 模型 | 大小 | 读格子色号（3 张糊图抽 1800 格） | 速度 | 读清单（12 张示例图） |
| --- | --- | --- | --- | --- |
| **高精度（默认）** PP-OCRv6 small | 12.2 MB | **97.6%** | 慢约三成 | 146 / 180 |
| 标准 PP-OCRv5 mobile | 7.7 MB | 91.1% | 最快 | **152 / 180** |
| （没采用）PP-OCRv6 medium | 62 MB | 97.7% | 慢 5 倍多 | 147 / 180 |

整条“逐格读色号”流程（颜色归类 → 读有风险颜色的格子 → 一起重新归类）按逐格真值数错格：镜子 174 → 标准 8 / **高精度 4**；镜子糊图 184 → 13 / **6**；IMG_8879 糊图 168 → 4 / **2**（原图 0 / 1）。所以读格子默认用高精度；读清单时两个模型差不多、低清清单上标准模型反而读对更多（试过两个模型合起来读也没更好），所以读清单一直用标准模型。更大的 PP-OCRv6 medium（62 MB）准确率和 small 一样、慢 5 倍，没有加。两个模型都随应用部署在 `vendor/ppocr/`，第一次用时下载（运行库和读清单共用），之后单独缓存、离线可用。

### 3. 实况文本 / 快捷指令（免费、不联网、不需要参数）

用 iPhone 自带的文字识别（Apple Vision）把截图里的字拷贝出来，粘贴到应用里解析：

- **实况文本**：照片里打开截图 → 右下角“实况文本”图标 → 长按选中清单文字 → 拷贝 → 回到应用点“从剪贴板粘贴”。
- **快捷指令**：新建快捷指令 → 添加“从图像中提取文本”（输入选“快捷指令输入”）→ 添加“拷贝到剪贴板” → ⓘ 里打开“在共享表单中显示”，类型只留“图像”。以后在照片里分享截图给它即可。

文字没有位置信息，只选清单那几行效果最好。可以同时附上截图，核对时对照看。

无论哪种方法，确认前都必须逐项人工核对，所以识别错的会在这一步被改掉。

**拼豆板数字化**（开始拼豆时自动把网格变成拼豆板）：为了能逐格评测，给 12 张示例图做了**逐格真值**（共 47,222 格，其中 30,228 颗豆子）：每一格先用 PP-OCRv5 读格子里印的色号，再和两种颜色归类的结果比，三方不一致的格子全部人工看图裁决，最后每种颜色的格数都和清单核对一致（IMG_8877 的 G9 图上比清单多 2 格，原样保留）。在这套真值上（按应用实际存图的质量评测）：

| | v2.0 | v2.2 |
| --- | --- | --- |
| 自动找对网格（行列数、每条线误差 ≤3 像素） | 8 / 12 | **11 / 12** |
| 网格正确时，逐格全对的格子 | 98.06%（错 917 格） | **99.20%（错 377 格）** |
| 每种颜色的格数和清单完全一致 | 117 / 180 | **179 / 180** |
| 逐格 100% 正确的图 | 0 / 12 | **7 / 12** |

**逐格读色号**（v2.5.1，只读“颜色很接近 / 和色卡差得多”那几种颜色的格子；v2.6 起默认用更准的高精度识字模型，见上面“识字模型”）：镜子那张（几种米白色只差 3–8 个色差单位，只看颜色分不开）在 App 里整条流程测过：149 → **4** 格错（高精度模型，读了 2431 格，无头 Chromium 上 63 秒；标准模型是 14 格、57 秒），读完再核对、重新计算也保持 4 格；IMG_8879 不用清单颜色也能 168 → 4。只读一部分格子再靠“传播”效果差很多（镜子读 600 格只到 142），因为几种米白色每一格都得看自己的字。

**清单色块颜色**（v2.5）：同一套真值上，按 App 存的图质量、开着去水印，错的格子 366 → **175**：IMG_8879 这张出图软件的色表和色卡差很多（G10、G19 按色卡色差了 24–26），以前 G10/G19 整种认反 168 格，用清单色块颜色后**全对**（整条流程也测过：OCR 读清单 → 在识别总览里点没读出来的色块补上 → 保存 → 生成拼豆板）；其他图没有变差。镜子那张低清 JPEG 的清单色块和格子颜色差了 1–10，几种米白色又只差 3–8，所以帮助有限（184 → 161）。

剩下的错误几乎都是“两种颜色几乎一样、格子里的字又太小”时整种颜色认反（比如 IMG_8879 的 G10/G19、镜子那张的 A1/G15/G18/H13 几种米白），这正是“核对拼豆板”要问的地方：模拟每种相近色回答一格、再在候选格里点出真正的那种，377 格错误降到约 205 格（IMG_8879 从 174 格错到全对）；让识字模型自动核对也能把 IMG_8879 纠正过来。没有格线、只有色块和棋盘格底纹的那张（IMG_8880）仍需要手动校准网格，校准后逐格全对。

## 自定义色卡

**设置 → 色卡管理**（点“色卡”那张卡片进入）：

- **改**：点任一颜色 → 可改色号、颜色、名称。颜色可以点左边的色块用 iPhone 调色盘选，也可以直接输 `#RRGGBB`，或点“📷 从照片取色”，在豆子照片上点一下取平均色。改过的颜色会标“改”，编辑时可一键“恢复内置颜色”。
- **增**：右上角“＋ 新增”。系列按色号前面的字母自动归类（如 `ZG1` 会新建 ZG 系列）。
- **删**：编辑页左下角“删除”。如果库存里还有这个色号，会先提醒，确认后库存记录一起删除（记入流水）。
- **改色号**：库存会自动转到新色号；已保存的图纸和流水里仍显示旧色号。
- **批量**：“批量导入 / 导出”里每行一个 `色号 #RRGGBB 名称`（名称可省略），适合一次加入另一个品牌的整套色卡，或复制到另一台设备。

自定义色卡保存在手机本地，识别（三种方法）、核对、库存都会立刻使用新的色卡；导出备份时会一起带上。

## 开始拼豆

图纸详情里点 **🧩 开始拼豆**（保存新图纸时也可以直接“保存并开始拼豆”）。

第一次进入先**准备拼豆板**，5 步，每一步一页（上面有步骤条，左上角可以一步步退回去；“下一步”固定在屏幕底部，不用滑到最下面找）：

1. **框选**：原图上已经自动框好（识别时算过的网格位置外扩一格），拖角调大小、拖中间移动、框外空白处重画；“整张图”/“重置”。不想用拼豆板可以点“不用拼豆板 ›”，只按颜色打勾。
2. **网格**：在框里找格线（识别时已经算好的话直接显示）。原图上每 5 格画一条红线，看看和格子对没对齐（点图全屏放大看）；卡片上写着 **图纸网格 X 列 × Y 行**、**有豆子的范围**（去掉四周空格后的宽×高）、**豆子总数**（和清单差得多时会提醒）。行列数不对就“手动校准”（填几列几行，在原图上点左上角、右下角）。认出来的颗数明显比清单少时（多半是框或者自动猜的清单位置切掉了网格边上的一两行），会自动把区域四周放宽 3 格再找一次，行列只多不少、颗数更接近清单才用。
3. **颜色**：颜色认得对不对都在这一页解决，选拼豆板尺寸之前，而且**不用点**：
   - **🔍 自动逐格读色号**：有几种颜色很接近（比如几种米白色）、或者图上的颜色和色卡差得多时，一进这一步就自动开始。用识字模型（默认高精度 PP-OCRv6 small；设置 → 识字模型 里可换成标准）把这几种颜色的每一格上印的色号读出来，和颜色一起判断；显示进度、还要多久。读的时候“下一步”先等着；不想等可以点“停止”（已经读了的会用上），之后也可以再点“开始逐格读色号”。镜子那张要读约 2400 格，电脑上 1 分多钟。读到的色号跟着拼豆板存下来，读得有把握的格子锁定，之后核对、重新认颜色都照样算进去，不会被冲掉。
   - **🙋 自动弹出核对**：读完色号（或者不用读）后，还有颜色很接近的、没把握的格子，就直接弹出“核对拼豆板”（见下面）。先读色号再核对，要核对的少很多（镜子那张 35 处 → 11 处）。关掉就是先不核对，卡片上的“开始核对”随时能再点；核对完不会再弹。
   - **每种颜色：拼豆板 / 清单**：格数对不上的颜色列在最上面（差得多的标黄），其余的只列出色块。某种颜色**没从清单色块取到颜色**（只能按色卡标准色认）、而且格数差得多或者图上颜色和色卡差得多（还没读色号时）时，旁边有“点色块”：点它，再在图上点它的色块（清单里的色块或者任意一颗这个颜色的豆子，别点到字和白底），网格不动、按你点的颜色重新认；点的地方在格子里找不到一样的颜色会告诉你再点一次。只是没取到清单色块、但按色卡色也认对了的颜色**不提示**。
   - **去水印** 开关（默认开，见下一节），“看效果”全屏对比去水印前后。
4. **尺寸**：“常用尺寸”默认 52×52、78×78、104×104，每个写着四周还空几列几行；**放不下整幅图（有豆子的范围比拼豆板大）的尺寸是灰的、不能选**。也可以输入宽×高“用这个尺寸”，或“存为常用”；常用尺寸右上角 ✕ 删掉。或者“按图纸原来的格子”。
5. **摆放**：默认居中。用 ↑ ↓ ← → 把所有豆子一起平移（按住连续移动），最多移到贴边，不会超出拼豆板；上面实时显示上下左右各空几行几列，“居中”一键回中间。浅色格子是拼豆板上空着的位置。点“完成，开始拼豆”。

之后再进来直接是拼豆板（设置都记住了）：

1. 拼豆板按你选的尺寸画，每 5 格一条粗线，位置和实物拼豆板一样：**52×52** 上下左右各空 1 行/列豆子再画第一条线，**78×78** 各空 4 行/列（左边第 4 列豆子右边是第一条线，右边第 4 列豆子左边也是），**104×104** 各空 2 行/列；中间都是每 5 颗一条。其他尺寸也是两边留得一样多；“按图纸原来的格子”时从边上开始画，和图纸上的线对齐。上边、左边标着 1、5、10、15… 的行列号（拼豆板上的位置）；双指缩放、拖动，双击放大。**放大后行号固定在屏幕左边、列号固定在上边**（格子够大时每一行、每一列都标，小一点时每 5 个标一个），拖到哪儿都能看到是第几行第几列。
2. 底部是这幅图的所有颜色（左右滑动；点颜色后这一排停在原位，不会跳回最左边），默认**颗数多的排在前面**（先把大面积的颜色拼上，剩下的小颜色有参照更好找位置）。最左边的 **⇅** 可以换顺序：颗数多的先拼 / 颗数少的先拼 / 按色号 / 按图纸清单顺序（会记住）。
3. **点一个颜色，板上分三种豆子**：
   - **正在拼的颜色**：原色（深）；
   - **已经拼好的颜色**：浅色（往白色掺淡，带一圈淡边，白色、米色的豆子也看得出来）；
   - **还没拼的颜色**：默认**先不画**，只留空钉——和手上的拼豆板一模一样，最好对照着找位置。
   也可以在 ⇅ 里换成 **“三种深浅”**：还没拼的也画出来，但最淡。两种方案比较后默认用第一种：半透明的三档对浅色豆子（白、米白、浅黄）几乎分不出来，而“像实物”只有深、浅两档，一眼就能分清。点板上的一颗豆子也能选中它的颜色，同时显示它在拼豆板第几行第几列。不选颜色（“全部”）时，已拼好的浅色，其余正常。
4. **✦ 高亮当前颜色**（缩放按钮旁边的“✦ 高亮”，或 ⇅ 里打开，会记住）：板子变暗，正在拼的颜色保持原色、外面一圈白边，一眼就能找到；其他颜色都压暗——已拼好的暗，没拼的更暗（“像实物”时没拼的照样不画）。没选颜色时不起作用。
5. **⇋ 镜像**（缩放按钮旁边，或右上角 ⋯）：整块板左右翻转显示，板上角落标着“镜像中”。点格子、行列号都按翻转后的位置算。再点一次取消。
6. 这个颜色拼完了，点 **✓ 这个颜色拼好了**：打上勾，按上面的顺序自动跳到下一个没拼的颜色。点错了可以“还没拼好”取消。
7. 全部打勾后出现 **🎉 全图已拼好**，点了会弹出“确定后将确定减少拼豆库存，是否继续？”，确定后扣库存并提示哪些颜色该补货。**照着拼豆板拼的，按拼豆板上每种颜色的豆子数扣**（清单和拼豆板认出来的数量不一样时，以拼豆板为准——照着它拼，用掉的就是板上的豆子）；底部颜色条、选中颜色时显示的颗数、图纸详情的“库存对照”、多选合计也都按拼豆板上的数（选中颜色时括号里写着清单上的数）。只按颜色打勾（没用拼豆板）时按清单数量扣。
8. **先拼到这里**（没全部拼完时底部的按钮，或右上角 ⋯ 里）：
   - 打了勾的颜色：扣库存（拼上去的豆子很难再挑下来）。
   - 没拼好的颜色：放回库存，不扣。某个颜色拼了一部分的话，可以展开“有颜色已经拼上去一部分？”填用掉了几颗。
   - 选 **以后接着拼**：进度保留，以后拼完只扣剩下的；选 **这次不拼了**：图纸放回 **待拼**，详情页会写“上次拼到一半没继续”（哪天结束、当时扣了哪些），再点开始拼豆是全新的一次。
9. **撤回为待拼**（图纸详情“拼豆中”卡片右下角，或拼豆页右上角 ⋯）：点了开始拼豆又不想拼了，就撤回——打的勾清空，这次拼豆扣过的库存全部加回来（流水里记一笔“撤销”），图纸回到“待拼”；拼豆板、尺寸、摆放位置都保留。和“这次不拼了”的区别：那个是豆子已经用掉了，扣的不退。第一次设置拼豆板时（还没看到拼豆板）直接退出来，图纸也还是“待拼”。
10. 扣过的库存都可以在图纸详情里“撤销扣减”（库存加回来，已打的勾保留）。

**右上角 ⋯**（旁边的 **📲 iPad** 见下一节）：
- **在 iPad 上拼（扫码）**：见下一节。
- **核对拼豆板**：和准备拼豆板“颜色”那一步自动弹出的核对是同一个（拼豆时想再核对就从这里进；以前读过的色号照样算进去）。每一步给你看原图上那一格的放大图（红框），问你“这一格是 G19 吗？”——
  - 答“是”：这一格锁定为 G19；答“不是”并选出它真正的颜色后，再给你看一页和它颜色很像的格子，点出所有写着 G19 的，点“下一步”。
  - 没把握的格子（“红框里这一格是？”）直接选颜色（或“空”）。
  - 两种题都有 **“其他颜色”**：列出这张图纸清单里的所有颜色和“空”，候选里没有的从这里选（清单里没有的颜色要先在图纸详情“修改颜色和数量”里加上）。
  - **← 上一题**：手滑点错了就退回上一题，刚才那一格的确认会撤掉（跳过、点格子那一页也能退回；从下一题退回“点出所有写着 G19 的格子”那页时，之前点选的还在）。随时可以“结束核对”，结束页也能退回上一题。
  - 最后“重新计算”：你确认过的格子全部锁定，整板按它们重新认一遍——确认一格往往能把整种颜色认反的问题一起纠正（锁定的格子会成为这种颜色在这张图上的“标准色”和“标准字形”）。
  - “🤖 先让识字模型自动核对相近色”：用识字模型（设置里选的那个）读这些颜色的几格，读得有把握的自动锁定（第一次要下载模型）。
- **拼豆板和清单对一对**：每种颜色板上几格、清单几颗。
- **修正格子颜色**：进入修正模式后点格子，选正确的颜色（或“空”）。改过的格子会锁定。
- **拼的顺序和显示方式**（和底部 ⇅ 一样）。
- **镜像 / 取消镜像**。
- **撤回为待拼**。
- **换拼豆板尺寸 / 调整位置**：回到第 4、5 步，拼豆板本身不重算；中途返回的话原来的摆放不变。
- **重新框选拼豆板 / 重新识别**：从第 1 步开始，重新识别网格（手动校准在第 2 步）；核对、修正过、读字锁定的格子保留。

## 在 iPad 上拼（拼豆看板）

拼豆板在 iPad 的大屏幕上看更清楚。**库存、图纸还是只在 iPhone 上**；iPad 上只放拼豆板本身和 iPad 上打的勾（存在这台 iPad 的浏览器里）。两台设备之间用二维码传，不经过任何服务器、不用登录。

**第一次**：iPad 用 Safari 打开网址后面加 `ipad.html`（比如 `https://你的用户名.github.io/pindou-app/ipad.html`；iPhone 上 📲 iPad 里可以复制）→ 分享 → **添加到主屏幕**，以后从主屏幕打开 **拼豆看板**。第一次扫码要联网下载扫码引擎（约 1 MB），之后不联网也能扫。

1. **iPhone → iPad**：iPhone 上开始拼豆 → 右上角 **📲 iPad**（或 ⋯ → 在 iPad 上拼）→ 出现二维码（屏幕不会自动变暗）。拼豆板大的分几张**轮流显示**（示例里 78×78、14 种颜色的一张是 4 张），每张都不密、好扫。iPad 上点 **📷 扫码接收拼豆板**，对准 iPhone 屏幕不动，收齐了自动打开拼豆板。第一次会问能不能用摄像头，点“允许”；iPad 放在支架上可以点“换摄像头”用前置的。
2. **在 iPad 上拼**：和 iPhone 上一样——选一个颜色只看这个颜色、✦ 高亮、⇋ 镜像（只改 iPad 上的）、缩放、固定的行列号、⇅ 拼的顺序和显示方式、✓ 这个颜色拼好了。横着放时颜色在右边一栏，竖着放时在底下。iPad 上可以存好几张拼豆板，关掉再开还停在原来那张，勾都在。
3. **拼完**：iPhone 上这张图纸的拼豆页面，底部多了 **🎉 全拼好了**（发到 iPad 之后才有，因为勾是在 iPad 上打的），点了按拼豆板扣库存。
4. **中途结算**（先拼到这里）：iPad 上点 **📤 进度传回 iPhone**，出现一个二维码；iPhone 上“先拼到这里”最上面（或 📲 iPad 里）点 **📷 扫 iPad 上的进度码**，iPhone 上的勾就换成 iPad 上的，再照常结算。
5. **iPhone 上改了拼豆板**（修正格子、换尺寸、重新识别）：iPhone 上再点 📲 iPad，iPad 上 ⋯ → 重新扫码；iPad 上打的勾保留。
6. 扫错了会提示，比如在 iPad 上扫了进度码：“这是 iPad 的进度码，要用 iPhone 扫”。iPad 上删掉拼豆板只删 iPad 上那一份。

测试：Chromium 的假摄像头播放“拍 iPhone 屏幕”的视频（二维码加了旋转、模糊、噪点，对比度也降低了），iPad 1–2 秒收齐 4 张，拼豆板和 iPhone 上逐格一致；iPhone 扫 iPad 的进度码同样。扫码用 ZXing-C++（WebAssembly）：同样的模拟画面 jsQR 基本读不出来，ZXing 大部分帧都能读，每帧约 10 ms。

## 去水印

有的图纸截图上盖着水印（大字的店名、半透明的 @作者名、斜着铺满的小字），会把格子染上别的颜色，导致认错色号。**开始拼豆 → 第 2 步“识别网格”** 里有 **去水印** 开关（默认开，关掉后整板按老方法重新识别；设置会记住）：

- **怎么做的**：同一张图纸上，同一个色号的格子本来**一模一样**（同样的底色、同样位置印着同样的字）。所以先正常认一遍，然后给每种颜色取它所有格子的**逐像素中位数**，得到这张图上这种颜色的“干净样板”——水印只盖住其中一部分格子，而且每格盖住的位置不一样，中位数会把它滤掉。认颜色时，每格和每个样板逐像素比（差得太多的像素截断，不让一大块水印主导），和原来的“颜色 + 字形”代价各占一半，再按清单颗数重新求一次最优解，重复两轮。这是用图纸本身的重复结构做的“基于样例的修复”，不需要任何训练好的去水印模型，手机上多花约 0.3 秒。
- **看去水印后的图**：开关旁边“看去水印后”：把每格和它颜色的样板对齐（±3 像素找最对得上的位置），和样板附近 5×5 都差很多的像素才换成样板的像素；看起来像格子里印的字（颜色落在“底色 → 字色”这条线上）的像素不动，所以即使某格色号认错了，原本印的字也不会被抹掉。核对拼豆板时的放大图也用去水印后的图。
- **效果**（12 张示例图、逐格真值，按应用实际存图的质量）：错的格子 395 → **366**；水印最重的 IMG_8875 从错 17 格到**全对**，IMG_8876 错 2 格到全对，其余没有任何一张变差。剩下的错误主要是几种颜色几乎一样的米白色互相认反，那要靠“核对拼豆板”读字。

没有原图的图纸（文字识别、手动录入、旧版本存的）不能生成拼豆板，但同样可以按颜色打勾、结算库存。不想用拼豆板的话，图纸详情最下面“不用拼豆板，已经拼完了 → 按清单数量直接扣减库存”一步扣完（按清单上的数量）。

## 多张截图拼成一张大图

一张图纸太大、拆成了几张截图（往下滑截了几张，或者作者切成上下左右几块发的）：**添加图纸 → 选图时一次选几张**，会先到“合并成一张大图”：

1. **自动拼**（几秒钟）：每两张比一比，找出重叠的那一段（先在缩小的图上用归一化互相关一次算出所有可能的错开位置，再在原大小的图上细调到逐像素对齐——拼豆图纸的格子是周期的，先比缩小后的图案再细调，就不会错开整格）；然后把重叠部分只留一份拼成一张。重叠的地方用离自己边缘最远的那张（截图边上常有水印、切了一半的格子）。
   - 选图的顺序乱了没关系；上下、左右、2×2 都能拼；重叠只有一两行格子也找得到。
   - 几张大小不一样（比如一张被压缩过）：先量每张的格子间距，缩放到一样再拼。
   - 拼好后显示整张预览（点开可以放大看接缝），“拼对了，用这张大图继续”。
2. **找不到重叠**（刚好切在边上，或者有一张只是清单）：显示每一块（已经拼好的几张算一块），**调顺序**（↑↓），选**上下拼 / 左右拼 / 每行 2 张…**，直接接在一起，下面实时预览。自动拼的结果不对时也可以点“不对，手动排”（按原来的几张直接接起来，不去重叠）。
3. 拼好的大图接着走原来的流程：框清单 → 识别 → 核对 → 保存；原图按拼好的大图保存（长边到 8192、1200 万像素以内保持原大小，拼豆板要读格子里的字），开始拼豆时整幅图纸都在一张拼豆板上。
4. 几张其实是不同的图纸：点“不合并，每张分开识别”（和以前一样每张分别框清单，结果合在一起）。

测试（从示例图切出来的 15 组：上下三块、顺序打乱、2×2、加水印 + JPEG、一张缩小到 0.8、只重叠 1 行、很长的三块，以及不该拼的：刚好切开、两张不同的图纸、单独的清单图）：该拼的全部拼对（和原图逐像素一致，位置误差 0），不该拼的都没拼；每组 0.5–3 秒（电脑上）。

## 识别总览：先看漏了哪个

识别完（云端大模型、离线 OCR）不会直接进入逐项核对，而是先到 **识别总览**：

- 清单图上每个识别出的颜色都有一个框：绿色 = 读出来了，黄色 = 把握不大，红色 = 缺色号或数量。默认只给黄/红框标出识别结果（不挡字），“显示全部标签”可以全部标上。
- **没有框的色块就是漏掉的**：直接点它，弹出放大的局部，按色块颜色推荐几个色号，填色号和数量后“添加”。
- 图上点不到的（比如清单被截掉一截、色块被挡住），点“＋ 补一个漏掉的颜色”选色号、填数量（可以先不填）。**补完仍留在总览**，可以接着对着整张图把颜色找齐，颜色都齐了再逐项核对数量。
- 点有框的地方会打开那一项去核对/修改。
- 清单又宽又扁时会切成几段上下排，字更大；也可以“⤢ 全屏放大”，在全屏里双指放大后点漏掉的颜色。
- “图上写的总颗数”：图上写了总数（比如标题里的 4613）就填进去，会显示比图上少/多几颗——少的颗数往往正好是漏掉那一色的数量。
- **和图纸上的格子对一对**：总览下面会自动把图纸网格数字化（几秒钟），不按清单凑数、只看图上的颜色和格子里印的字，数出每种颜色大约几格：
  - 某种颜色图上的格数和清单差很多：多半是这个色号或数量读错了（图上一格都没有时会问“色号是不是认错了”）；颜色几乎一样的几种会合起来比总数。
  - 图上有一团颜色清单里没有：会给出颜色和最像的色号，提示“是不是漏了”。
  - 这一步算出的拼豆板会跟着图纸保存（清单后来没改的话），开始拼豆时直接打开。
- 看完点“没漏，开始逐项核对”。核对中随时可以点右上角“总览”回来。
- 没有框的识别结果（实况文本附了截图、或者识别方法没给出位置）会先到 **“先看颜色齐不齐”**：上面是完整原图（点开可放大），下面是已经识别出的颜色；缺哪个就“＋ 补一个漏掉的颜色”，颜色齐了再点“颜色齐了，开始核对数量”。

## 多选图纸：算合计 / 一起删除

**图纸 → 右上角“多选”**：

1. 勾选打算拼的图纸（可以先用上面的状态/分类筛选，再点“全选”）。
2. 点“看合计用量”。每张图纸右边可以改“份数”（同一张拼两次就设 2 份）。
3. 表格里：**需要**（已含损耗）、**现有**、**拼完剩**（负数显示“缺 N”）、**建议买** = 拼完后补回到补货线所需的数量。
   - 红色：库存不够拼完这些图；黄色：够拼，但拼完会低于补货线。
   - “要买的”只看需要买的颜色；点一行可展开每张图纸各用多少。
4. “复制采购清单”把要买的颜色和数量复制出来，可以直接发给店家。

合计只是计算，不会改库存。

**一起删除**：多选模式底部左边的“🗑 删除 N 张”。确认框里列出要删的图纸名字；其中已经扣过库存的（已拼完、或拼到一半结算过）会提醒“删除后不会加回来”——要加回来请先在那张图纸里“撤销扣减”或“撤回为待拼”。原图一起删除，删除后不能恢复。删完回到普通列表。

## 拼豆板是怎么认出来的

1. **找网格**：统计每一行/列上“比两边都暗或都亮的细线像素”的个数得到剖面，用自相关的各次谐波定格子边长，用“梳子”对齐相位，逐条找峰再做稳健直线拟合；横竖边长不一致时两个候选都试，梳齿对得最齐的赢。格线很浅、每格又印着字时，字的那一行也会形成周期峰，所以再用“色块交界”（两边各自平稳、彼此差很多的台阶）校一次相位。两头：去掉写着行号/列号的表头（整排同色、每格有字、而且 1–9 一位数、10 起两位数），格线太浅没找到的最后一两行/列按“颜色都是网格里已有的颜色、旁边的编号栏还在继续”往外补。
2. **每格的特征**：底色（中位数附近的平均）、格子里最多 3 团颜色和各自占比、字形（格子中间 24×14 的“和底色差多少”图，按全图平均字形对齐 ±2 像素）。
3. **颜色**：**先看清单**：识别清单时，每个色号在图上的色块颜色会记下来（取色块里最多的前 3 种颜色当候选；识别总览里点图补上的颜色，也从整张原图上取）。清单色块和格子是同一个软件、同一次压缩画出来的，通常和格子颜色一模一样——比“色卡标准色 + 校准”准得多，尤其是出图软件的色表和 MARD 色卡差得多的图。但取色可能取歪（取到字、白底、隔壁色块），所以只有“图上确实有一批格子就是这个颜色、而且离这个色号的色卡色不算太远”的候选才采用，两个色号抢同一个颜色时给离色卡色更近的那个；采用了的直接当这一色的参考色（第一轮就用，校准不动它），“识别网格”那一步会写“按清单色块的颜色认 N / M 种”。没取到的色号（文字识别、旧图纸、手动补的）照旧：先用色卡颜色粗分一遍，再用各色号格子的中位色拟合“色卡 → 这张图”的稳健仿射变换（Huber 权重，认错的色号当离群点），比较用 CIEDE2000 色差；再加“覆盖率”（这一格里有多少像素就是这个颜色），被水印、半透明浮层染色的格子一看就不像任何豆子。离所有颜色都很远的格子（界面浮层、贴纸）不拿来凑颗数。色卡和出图软件色表不一致、只有几颗的颜色，用“没人认领的颜色团”去配。
4. **格子里印的字**：每个色号的字形模板从这张图自己学（归到这个色号的格子的平均字形），每格和每个模板比均方差（按图的清晰度归一化、截断）。白豆和白底、颜色几乎一样的两种豆子主要靠它分开。
5. **清单颗数**：把“颜色代价 + 字形代价”交给带软约束的最小费用流：目标是 Σ 代价 + ρ·Σ|格数 − 清单颗数|，从“各选最便宜”出发在“色号图”上反复找负环消去（Bellman-Ford），没有负环时就是全局最优（开发时和显式网络上的逐条最短增广路对比了 300 个随机例子，结果全部一致）。颜色、字形模板、归类交替更新三轮。
6. **核对**：颜色很接近、图上颜色和色卡差得多、或者归进来的格子和参考色对不上的色号，列为“身份有风险”；没把握的格子按“换成别的色号要多花多少”（含对偶势）排序。你确认的格子变成硬约束，同时成为这种颜色在这张图上的标准色和标准字形，整板再解一遍。

## 小红书上的图纸不清楚怎么办

小红书 App 里“保存图片”存下来的是压缩过、加了水印的版本，所以比在 App 里看的时候糊。拼豆计数器没法直接粘贴小红书链接来取图：小红书不允许程序自动读取笔记（网页的 robots 规则禁止，而且要登录账号的 cookie、页面结构也经常变），要做就得把你的小红书登录凭证交给一个服务器，不安全也不稳定。更好的办法：

- **截屏代替保存**：在小红书里把图纸点开全屏看，直接截屏（截屏不会再压缩）。清单部分字小的话，双指放大到清单再截一张。
- **添加图纸时一次选多张**：整张图纸那张放第一张（拼豆板用它生成），清单放大截的几张一起选，识别结果会自动合并。
- 用别的软件把高清原图存进了相册的话，添加图纸时照常从相册选就行。
- 清单特别糊的，识别方法用“云端大模型”，比离线 OCR 读得准；识别完的“逐项核对”和“核对拼豆板”也能把读错的改过来。

## 放大看原图

识别（大模型、OCR，或文字识别时附上的截图）时，整张图纸会自动存进本地数据库，所以识别完也能随时放大看：

- **核对页**：参考图下方“🔍 放大看清单”（直接放大到当前这一项）/“🖼 看完整原图”；点参考图本身也能打开。列表模式点“🖼 看原图”。
- **保存图纸**：名称旁的“🖼 看图纸”。
- **图纸库 / 图纸详情**：点图纸的缩略图；拼豆时右上角 ⋯ → 看原图。
- 看图时：双指缩放、单指拖动、双击放大 / 还原；底部“清单 / 整张图”切换，“适合”看全图，⌖ 跳到当前核对的那一项；多张图用右上角 ‹ › 翻页。

原图跟着图纸保存；删掉图纸、放弃识别时原图一起删除，App 启动时也会清理没人用的原图。旧版本存的图纸没有原图。

## 数据与隐私

- 库存、图纸（含原图）、流水、设置都存在这台手机的浏览器（IndexedDB）里，不上传。
- 直连模式下 API Key 存在手机本地；导出备份默认**不含** Key。
- 云端识别时，截图（清单部分）会发给你选的服务商。
- 在 iPad 上拼：拼豆板和进度用二维码在 iPhone、iPad 之间直接传，不经过任何服务器；iPad 上只有拼豆板和打的勾，没有库存。
- 建议定期 **设置 → 导出备份**，“存储到文件”放进 iCloud 云盘；换手机时导入即可。
